## Finding

The batch runner's `docker run` lacked `--network none`. The now-retired
reconnaissance jobs also ran plugin code in networked containers. This
contradicted `docs/security.md` S2. All 24 reports already in the catalogue
were produced before the correction and therefore do not demonstrate the
promised no-egress property. All 24 contain absolute container paths; 20
contain verifier-authored replay fixture text. The site and README disclose
these limitations without rewriting immutable reports.

## Changes

1. A networked container resolves an **exact** package version and downloads
   its dependency files with pnpm lockfile-only resolution and `pnpm fetch`.
   It runs no install scripts and rejects lockfiles mentioning git, file or
   link dependencies before fetching.
2. A fresh container receives that subject's private package store, sets pnpm
   offline mode and starts with `--network none`. CPU, memory, process count,
   wall clock and writable storage have hard limits. The root is read-only;
   bounded tmpfs mounts total 5 GiB. A first-party idle container keeps the
   cache mounted between fetch and execution. All containers and the store are
   discarded after the attempt.
3. An offline-cache miss is `inconclusive`, not an install failure. The report
   upload now includes only validated final reports and timings, not raw pnpm
   or execution logs.
4. The obsolete networked probe jobs were removed from `verify.yml`.
5. `stale` now compares the registry integrity for the **exact reported
   version** with the bytes recorded in the report. A mismatch is marked stale
   for investigation; missing metadata is unknown.
6. Execution evidence now redacts container paths, credential-shaped strings,
   replay text and session identifiers before entering a report. The image's
   content-addressed local ID is recorded in every new execution report.
7. A first-party fixture reads the running plugin manager's declared bundle
   rows and Host fiber phases for L2. Missing inventory is inconclusive. A
   declared browser client stays inconclusive until it is observed in a
   credential-free browser container.
8. A container killed before writing phase results now produces a valid report
   with timeout or inconclusive dimensions and the orchestration exit code.
9. Transient prefetch failures and execution containers that produce no usable
   phase result retry once while the 420 s subject budget remains. A
   deterministic non-registry policy refusal and a completed plugin failure
   are reported immediately; retry counts are recorded in new reports.
10. Standalone badges from historical reports now carry the isolation incident
    in their SVG tooltip, including badges generated with the CLI.

## CI attempts

The maintainer-controlled [run 37168135780](https://github.com/citrusli2026/dsh-verified-plugins/actions/runs/37168135780)
successfully built the image, completed registry prefetch, and ran the executor
with `--network none`. It produced a valid `partial` report: L1 was
`inconclusive` because Corepack tried to query `pnpm/latest` inside the offline
container. L2, L3 and L6 were skipped; L5 was inconclusive. This is evidence
that the network boundary denied the request, **not** evidence that the full
offline flow works. The next revision set Corepack's documented offline and
default-version controls. [Run 37168565929](https://github.com/citrusli2026/dsh-verified-plugins/actions/runs/37168565929)
showed that Corepack still selected its own pnpm 11.24.0 for the unprivileged
user and tried to download it. The request was denied, and the new report
contained no absolute paths or replay text. It incorrectly classified the
Corepack failure as L1 `fail`; the classifier now treats that error as
`inconclusive`. The image now installs the pinned pnpm binary directly instead
of relying on Corepack's user-specific cache.

[Run 37168938885](https://github.com/citrusli2026/dsh-verified-plugins/actions/runs/37168938885)
shared the pnpm metadata cache and completed L1, L3, L5 and L6 under
