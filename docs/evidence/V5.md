## 2. Badges

```
https://citrusli2026.github.io/dsh-verified-plugins/badge/dsh-cost-meter.svg
```

Four states, four colours: `verified` green, `partial` amber, `inconclusive`
grey, `not-installable` red. Deliberately **not** a gradient or a scale — the
states say *how much ran*, not how good a plugin is, and a ranking is what made
the existing ecosystem signal untrustworthy.

Three properties the badge carries:

1. **The disclaimer travels in the SVG `<title>`**, because a badge is the
   artefact most likely to be seen with no report attached:
   > dsh-verified: verified — npm:dsh-cost-meter@1.8.8. Verification is not a
   > security audit and not an endorsement. It records what was executed and
   > observed on one machine at one time.
2. **An unknown verdict renders as `inconclusive`** rather than being published
   as a new state. A tool that invents a fifth colour is a tool nobody can
   trust the other four of.
3. **Everything interpolated is escaped.** A badge is small, but "it is only a
   badge" is not a reason to emit markup unescaped from third-party metadata.

## 3. The site

Twenty-five pages, no framework, no client-side JavaScript, no network. The
property that matters is not appearance:

> **Every dimension links to the evidence entries it cites**, and every evidence
> entry has an anchor. Verified on the live page: 7 dimension rows, 10 evidence
> links, 10 anchors, every link resolving.

A dimension that cites nothing renders as `no evidence cited` rather than
looking merely bare — the same rule the validator enforces, made visible to a
reader.

Report content derives from third-party package metadata and from command
output, so **all of it is escaped**. A test feeds a package whose `repository`
field is `https://example.test/<script>alert(1)</script>` and asserts that no
`<script>` reaches the page.

### The survey page

`/survey/` renders the 250-package survey: which packages declare a bundle, and
which of those the pinned runtime would refuse. It is the finding from V4 made
readable — 240 declare a bundle, 130 are peer-compatible, 110 would be refused.

## 4. Deployment is a maintainer step, on purpose

The site is built and pushed to a `gh-pages` branch **from a checkout**, not by
a workflow. This is a deliberate trade, not an oversight:

- deploying from CI needs `pages: write` and `id-token: write`;
- P0 keeps write permissions out of this repository entirely, and
  `tools/policy/check-workflows.mjs` fails the build on any `: write`;
- the alternative — carve an exception for "a workflow that runs no plugin
  code" — would mean the guardrail's first exemption, and exemptions are how
  guardrails die.

`ci.yml` therefore **builds** the site on every pull request, read-only, and
asserts one badge per report. Nothing deploys.

The cost of the trade, stated: **the site does not update automatically when the
catalogue changes.** After a batch that publishes new reports, a maintainer
re-runs two commands. That is recorded as an open item, and it is the honest
price of not handing a workflow a write token.

## 5. CLI

```sh
node packages/cli/src/main.ts site  [--out <dir>] [--survey <file>]
node packages/cli/src/main.ts badge <report.json> [--out <file>]
```

`packages/cli/package.json` declares the `dsh-verified` bin with **zero
dependencies** — the CLI runs straight from TypeScript via Node 24's type
stripping, so there is no build step and no `node_modules`. Direct execution is
verified (`./packages/cli/src/main.ts --help`).

`npx dsh-verified` needs the package on npm, and **publishing is a maintainer
decision this project does not take on its own**; the manifest is marked
`private` for that reason. From a checkout the supported invocations are direct
execution or a local install. (The `npm exec` path could not be exercised here
because this workspace's npm cache is root-owned — a documented local
constraint, not a packaging defect.)

## 6. Verified / not verified

**Verified:** the site builds from `catalog/` with no network and no client
JavaScript; every dimension links to resolvable evidence; nothing unescaped
reaches a page; the badge vocabulary is closed and scoreless; the live URLs
return 200 and the served page carries its evidence anchors.

**Not verified:** rendering in an actual browser (the checks are over the served
HTML and SVG, not a DOM); accessibility beyond the `role`/`aria-label` on the
badge; the site's behaviour at scale (25 pages, not thousands).

**Not done:** automatic deployment; a `badge/<owner>/<repo>.svg` path keyed by
GitHub repository rather than by package (the subject is an npm package, so the
path is keyed by package name — see `docs/schema.md`).

## 7. Reproduce

```sh
node packages/cli/src/main.ts catalog                 # rebuild the index
node packages/cli/src/main.ts site --out site-dist    # render the site
node packages/cli/src/main.ts badge catalog/npm/dsh-cost-meter.json
node --test packages/report/test/*.test.ts
```

Deploy, from a checkout:

```sh
node packages/cli/src/main.ts site --out /tmp/site && touch /tmp/site/.nojekyll
cd /tmp/site && git init -b gh-pages && git add -A && git commit -m publish \
  && git push -f git@github.com:citrusli2026/dsh-verified-plugins.git gh-pages
```
