## 4. Findings

### F1 — npm silently skips install scripts for the DSH runtime (medium)

The first container build (run `37129367431`) reported:

```
npm warn install-scripts 5 packages have install scripts not yet covered by allowScripts:
npm warn install-scripts   @deepseek-ai/dsh-subprocess-local@0.2.0-rc.2 (postinstall: node scripts/ensure-spawn-helper.mjs)
npm warn install-scripts   koffi@3.1.1 (install: node ./cnoke.cjs -P . -D src/koffi --prebuild --release)
npm warn install-scripts   node-pty@1.2.0-beta.15 (install: node scripts/prebuild.js || node-gyp rebuild; postinstall: node scripts/post-install.js)
npm warn install-scripts   @google/genai@2.21.0 (preinstall: echo 'preinstall: no-op')
npm warn install-scripts   protobufjs@7.6.6 (postinstall: node scripts/postinstall)
```

Two of those are **native modules**. `dsh --version` answers anyway, so a
half-built runtime is invisible until a feature needing the natives is used —
and every later measurement would be quietly wrong.

**Decision:** the container allows exactly these five, for the **first-party
runtime only**, explicitly and in the Dockerfile. Third-party subject plugins
never get this treatment; their pending build scripts are a reportable finding,
not something to approve. The decision is recorded in
`/opt/dsh-runtime-facts/install-scripts.txt` inside the image, and the current
image correctly shows **no** gating warnings because the scripts are now
allowed.

The obvious follow-up — whether DSH's own install path should ship these
allowances — is an upstream question, not this project's call.

### F2 — the official keyless replay plugin is not installable against current DSH (high)

> **CORRECTED — see [L3.md](L3.md).** This finding was reached by resolving the
> package by bare name, which yields the `latest` dist-tag: `0.0.1-rc.1`, from a
> much older runtime generation. `@deepseek-ai/dsh-llm-replay@0.2.0-rc.2` exists,
> its peers match the pinned runtime exactly, every binding it imports is present
> in the `0.2.0-rc.2` modules, and it installs cleanly in the container. The
> analysis below is accurate **for the version it examined**; the conclusion
> drawn from it was not. The text is kept rather than rewritten so the change is
> visible.

`@deepseek-ai/dsh-llm-replay@0.0.1-rc.1` is exactly the right tool for L3: it
"short-circuits `llm/stream` with model chunks reconstructed from a recorded
session JSONL (**keyless snapshot tests**)". It exists, and its interface is
documented and usable (`installLlmReplay`, `loadSessionScripts`,
`deriveReplayScript`, config `file`/`overrideFile`/`childFiles`).

But its declared peers cannot be satisfied:

| Declared peer | Required | Reality |
|---|---|---|
| `@deepseek-ai/dsh-compact` | `^0.0.1-rc.1` | **404 on npm — the package does not exist** |
| `@deepseek-ai/dsh-llm` | `^0.0.1-rc.1` | exists only at `0.0.1-rc.1` under `latest`; current is `0.2.0-rc.2` |
| `@deepseek-ai/dsh-session` | `^0.0.1-rc.1` | `0.0.1-rc.1` |
| `@deepseek-ai/dsh-invariants` | `^0.0.1-rc.1` | `0.0.1-rc.1` |

A caret range on `0.0.x` pins below `0.0.2`, so **`0.2.0-rc.2` cannot satisfy
`^0.0.1-rc.1`** under any resolution. Combined with the missing `dsh-compact`,
the replay plugin cannot be installed cleanly at the current DSH version.

**Consequence for V1:** L3 (`免密钥可复现运行`) is **blocked on the official
replay plugin** as published. The options, in preference order:

1. Run L3 against an older pinned DSH runtime whose peers match — cheap, but
   scopes the L3 evidence to an old runtime.
2. Implement the sanctioned fallback: a recorded transcript replayed by our own
   adapter.
3. `--allow-scripts`-style peer relaxation — **rejected**: papering over a peer
   mismatch would make the report lie about installability.

This is itself a public finding worth reporting, and it is exactly the class of
problem the project exists to surface: a first-party package whose declared
compatibility does not hold.

## 6. Verified / not verified / blocked

**Verified:** container builds and runs in CI; image is self-contained with zero
network; egress denial is observable and observable-denied; the install path has
a measured fixed overhead; the policy checker is non-vacuous; R5 now catches
execution hidden behind a script call.

**Not verified:** anything about any third-party plugin (that is V1); the image
reproducing bit-for-bit on another host; behaviour on non-x64 or non-Linux.

**Blocked:** L3 via the official replay plugin (F2). Local container execution —
this workspace has **no** container runtime (no docker, colima, podman, nerdctl)
and Docker Hub is unreachable, while `registry.npmjs.org` is. V0 acceptance
therefore runs on a GitHub runner, which is the correct place for it anyway.

## 7. Known gaps carried forward

1. **The image is not published by digest.** `repoDigests` is empty because it
   is built locally and never pushed. True reproducibility needs the verifier
   image on a registry, referenced by `@sha256:…` in every report. V1
   prerequisite.
2. **No static type gate.** Node 24 strips types without checking them, and
   installing a compiler in PR CI would either trip the execution policy or
   weaken it. The trade-off is accepted for now and must be revisited; it is not
   silently ignored. Mitigation: the runtime path is exercised by real runs.
3. **`--network none` is binary.** A true egress allowlist needs a proxy or
   sidecar. `docs/security.md` § S2 states this rather than implying otherwise.
4. **664 MiB image.** Multi-stage build not yet done.
